04

Working well

  • Strength
    Skill-building as leverage, not just personal speed.

    13 distinct skills carried 46 invocations this month — forge-eval-3, gather-cohort-data, provision-cohort-infra, setup-bootcamp-repos. Cohort operations that used to be re-explained each time are now encoded once and reused.

  • Strength
    Plan before touching production infrastructure.

    The first non-us-east-1 region cutover started with a written design and implementation plan, committed before any live provisioning — the right sequence for a first-of-kind, deadline-bound change.

  • Strength
    Defects get closed into the system, not patched around.

    Runbook gaps found live during the ap-south-1 rollout were written back into the provisioning skill immediately, and a scoping issue from cohort 7 was filed as a structural follow-up rather than a one-off fix.

  • Strength
    Security work runs as a dedicated pass, not firefighting.

    The bedrock-proxy hardening — SSH removal, port closure, IAM scoping, secrets management, audit logging — landed as one coherent effort rather than a string of reactive patches.

  • Strength
    Model selection tracks task difficulty.

    Opus usage swung from 27% to 74% across the month, and every swing maps to a real reason — mandated grading, a security-critical rebuild, a first-of-kind region migration. The lightest week ran mostly on Sonnet.

  • Strength
    Corrections are paid for once.

    Shell-dialect mistakes, infra path assumptions, and PDF-format variance are all recorded with the why and the fix, so the same live incident doesn't recur across cohorts.

05

Costing time

  • Friction
    Shell-dialect assumptions still cause live redos.

    Three separate zsh-vs-bash incidents this stretch — unquoted word-splitting, a bash-only array expansion, an associative-array feature stock bash doesn't support — each caught mid-task rather than prevented. The fix (write multi-line or loop logic to a file and invoke it explicitly) is known but not yet the default.

  • Friction
    Infra assumptions surface live instead of being checked first.

    Both the infra workspace path and a pinned database engine version turned out stale mid-task. A short verification step before the first live command — the same instinct already applied to the ap-south-1 cutover — would catch these earlier.

  • Friction
    Team-membership gaps compound across cohorts instead of closing.

    Every recent cohort — C4 through C8 — currently carries an open org-access or missing-handle gap. Nothing forces this to zero before the next cohort starts; it currently gets caught up on, not closed out.

06

Next month

  1. Move infra verification earlier.

    Apply the ap-south-1 plan-first pattern one step earlier: confirm region, workspace path, and engine version against the live state before the first command in any provisioning skill, not partway through.

  2. Default shell logic to a file, not an inline heredoc.

    Any multi-line or loop shell logic in a skill gets written to the scratchpad and invoked as an explicit bash script.sh — closes the zsh/bash gap structurally instead of re-discovering it per cohort.

  3. Make the team-membership check a standing pre-cohort gate.

    Add a go/no-go item to cohort kickoff: zero open org-access or missing-handle rows before day one, not a backlog carried forward.

  4. Evaluate sharing the highest-reuse skills with co-facilitators.

    forge-eval-3 and gather-cohort-data are the two most-invoked skills this month. Turning personal leverage into team leverage is the next lever available as a lead, not just a personal one.

  5. Keep the plan-first, defects-into-the-runbook posture as default.

    It's the reason the next non-us-east-1 cohort won't repay this month's discovery cost — worth protecting deliberately, not assuming it repeats on its own.
